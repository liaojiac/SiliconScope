# 01 · 开发文档（产品需求 / 功能 / 评分口径 / 版本演进）

> 本篇讲「做什么、为什么这么做」，不讲代码实现细节（实现见 `02_技术文档.md`）。

---

## 1. 产品背景与目标

CPU「体质（硅晶圆质量差异）」决定同型号 CPU 在同样频率下需要的电压高低：体质好的核心能用更低电压
跑到目标频率，发热/功耗更低、超频空间更大。主板厂商 BIOS 通常内置闭源的工厂熔丝体质分（SP），
但普通用户在系统里看不到、且不同厂商口径不互通。

本软件的目标：用**可复现、可校验、不依赖任何厂商闭源分数**的方法，在用户自己机器上、于**全核满载
稳态**下测一个工作点（频率 F、电压 V），沿该 CPU 的 V/F 直线折算到统一锚点频率后与参考电压比较，
得到 0–150 的体质分与五档评级，并给出核间 VID 相对分布。

设计原则（贯穿所有版本）：
- **稳态、满载、可重复**：只在满载稳态采样，短窗口/偶发冲高/刚满载都不算数。
- **宁可拒评，不给假分**：环境不满足、数据不合理、中途掉载都直接拒绝并说明原因。
- **诚实标注不确定性**：未真机校准的型号标 `Estimated` 并显著水印，绝对分仅供同型号横向比较。
- **安全第一、便携优先**：不要求关闭任何系统安全功能；绿色文件夹、本地存储、不联网。

## 2. 用户与典型使用流程

目标用户：硬件爱好者、超频玩家，想量化自己 CPU 体质、对比同型号、挑核心。

标准操作流程（对应界面 4 步向导）：
1. **环境自检（Step 0）**：管理员权限、内核隔离兼容性（恒通过，仅展示）、LHM/PawnIO 驱动实测
   （真实读到传感器并显示数量）、基准量表 baseline.json 是否加载。任一硬性项不过则不允许继续。
2. **等待满载（Step 1）**：提示用户运行任意烤机工具（OCCT / Prime95 / Y-Cruncher / AIDA64 / CPU-Z）。
   界面 800ms 刷新一次实时频率/电压/温度与满载状态灯；同时做**持续满载稳定确认**（见 §4）。
3. **多点采样（Step 2）**：持续满载满约 1 分钟后**自动触发**（也有手动按钮，但门槛相同），
   进行约 10 秒（500ms × 20 轮）稳态连续采样，实时画 V/F 散点。
4. **评分完成（Step 3）**：显示「评测完成」，自动跳转评分详情页，落本地历史；完成页提供
   「↻ 重新评测」「查看评分详情」（修复评测完成后无法重测、只能重启的问题）。

四个导航页：**开始评测 / 评分详情 / 本机历史成绩 / 设置**。

## 3. 功能清单（按模块）

### 3.1 采集
- LHM 0.9.6 读 CPU/主板传感器：整颗核心电压（VDDCR / SVI2 TFN）、平均频率、封装温度、每核 VID/频率。
- 全进程只打开一次 `Computer`（PawnIO 驱动只加载一次），之后每次仅 `Update`。
- 跨主板弹性命名匹配（精确名 → 包含关键词 → 排除词），外加与命名无关的数值合理性兜底。
- 可选 HWiNFO 共享内存增强：正确解码 Zen4/Zen5（SVI3）的每核请求 VID；连不上静默回退 LHM。

### 3.2 质控与门禁（三道，顺序固定）
1. **合理性校验** `RationalityCheck`：电压 0.20–1.60V、温度 0–105℃、平均频率 500–7000MHz。
2. **满载判定**：平均频率 ≥ 全核 MaxBoost × 0.90（基准是 MaxBoost，不是基础频率）。
3. **质控门禁** `QualityGate`：电压 0.2–1.5V、温度 0–100℃。
- 采样窗口内满载轮次占比 < 80% 直接判失败重测（防中途掉载仍出分）。

### 3.3 评分
- V/F 线性折算到锚点频率后与参考电压比较，输出 SP（0–150）、五档评级、置信度、模式、最佳/最差核心。
- 三级参数解析（量表显式值 → 代际默认/MaxBoost 推算 → 曲线兜底），可选本机 V/F 自标定拟合。
- 报告/界面显著标注估计值（Estimated）与口径提示。

### 3.4 每核 VID 分布
- 仅做核间**相对排名**（VID 最低=请求电压最低=相对最好核心），不参与主 SP 分。
- 数据有效性 `PerCoreVidQuality`：满载时每核 VID 最大值需 ≥0.75V，且与整颗 VDDCR 差距 ≤0.25V；
  不满足（典型：LHM 在 Zen4 上给出 ~0.43V 占位值）整组置 null，不输出分布，避免「最佳=最差」假结论。

### 3.5 历史成绩
- 每次评测完成自动存程序目录 `history/score_yyyyMMdd_HHmmss.json`，本地、不上传，默认保留 100 份。
- 历史页列表查看、双击看详情、删除、打开目录；进入历史页自动重新扫描。

### 3.6 设置项（`settings.json`，程序同级目录）
| 设置 | 默认 | 含义 |
|---|---|---|
| EnableHwinfo | true | 自动探测 HWiNFO 共享内存取每核 VID，没有则回退 LHM |
| MultiSample | true | 约 10 秒多轮稳态采样；关闭则只采 1 轮 |
| FullLoadThreshold | 0.90 | 满载频率门槛 = MaxBoost × 该值 |
| SelfFit | false | 用本机多点拟合 V/F 斜率覆盖量表（要求 R²≥0.90） |
| LogLevel | Info | Verbose/Info/Warn/Error |
| RetainReports | 10 | 诊断报告保留份数 |
| RetainHistory | 100 | 本机历史成绩保留份数 |

## 4. 关键产品决策与「为什么」（接手前务必理解）

1. **为什么采样要约 10 秒、20 轮？**
   早期 5×150ms≈0.75s 太短，单次 `Update` 会抓到 P-State 切换瞬时值（真机出现过 0.43V 离谱低值），
   用户反馈数据失真。10 秒窗口取均值（电压/频率/温度）能稳定反映满载稳态工作点。

2. **为什么要「持续满载满 1 分钟」才自动采样？**
   用户可能刚启动烤机、频率电压温度还没稳定就点采样，也可能只是 CPU 瞬间冲高到门槛。
   `FullLoadStability` 用 60 秒滑动窗口：窗口覆盖 ≥98% 且满载占比 ≥90% 才判定稳定并自动触发；
   中途掉载计时回退。手动「立即采样」按钮用的是同一个门槛，不达标点不动。

3. **为什么满载门槛用 MaxBoost×0.90 而不是基础频率或 0.95？**
   真机 7800X3D（MaxBoost 5000）OCCT 重负载受功耗/电流约束，全核稳态只有约 4526MHz；
   0.95 门槛 4750MHz 会把真满载误判为未满载。0.90→4500MHz，既能容纳 Prime95 AVX-512/撞功耗墙
   （可低至 4.3GHz 量级），又不会放行轻载。**该阈值只决定能否评分，不参与分数计算**；不同负载的
   工作点差异交给 V/F 折算统一。

4. **为什么主分用整颗 VDDCR、每核 VID 只做排名？**
   Zen3/4/5 是统一供电（VDDCR），物理上不存在每核独立电压；LHM/HWiNFO 的「Core #N VID」是各核向
   供电系统发出的 **CPPC 请求值**，不是真实供电、也不是工厂熔丝分。真实供电口径只有整颗 VDDCR，
   故主分用它；请求值可用于核间相对高低排名。

5. **为什么每核 VID 要借助 HWiNFO，而不是直接用 LHM？**
   LHM 0.9.x（含当前 master）读每核 VID 是取 MSR 0xC0010293 的 CurCpuVid，再按 **Zen1~Zen3 的 SVI2
   公式** `Vcc=1.550−0.00625×code` 解码；Zen4/5 已改 **SVI3** 编码，LHM 仍套 SVI2 公式，于是 Zen4
   满载 8 个核都被解到 ~0.43V 最低档占位值。HWiNFO 用自有驱动正确按 SVI3 解码。本软件通过 HWiNFO
   **公开的共享内存协议只读**获取，不装驱动、不改硬件、不要管理员（共享内存只读）。
   - HWiNFO v7 起「共享内存支持」默认关闭，需用户在设置里勾选并重启 HWiNFO；免费版每 12 小时失效。
   - 不开 HWiNFO **不影响主 SP 分**（自动回退 LHM），只是没有核间分布图。

6. **为什么不要求关内核隔离/内存完整性？**
   LHM 0.9.6 用的 PawnIO 驱动兼容 HVCI，真机在内存完整性开启时能正常读到 74 个传感器，
   CPU-Z/AIDA64/OCCT 同样不需要关。早期版本曾错误地把 HVCI 当否决项，已废除。**安全功能永远开着。**

7. **为什么分数仍叫 SP 但去掉「对标华硕」？**
   SP 已作为分数名贯穿数据结构/界面/报告；已去除全部与厂商内置分数挂钩的表述，
   明确这是自研、可复现、不与任何厂商闭源分数对标的评分，避免误导用户以为能复刻工厂熔丝分。

## 5. 评分体系（产品口径）

### 5.1 分数与评级
- SP 绝对分：以 100（=参考电压）为中心，`SP = clip(100 + (VRef/V_anchor − 1) × 300, 0, 150)`。
  电压越低分越高。
- 五档（SP 轨，每档 8 分，关于 100 对称）：

| 档位 | SP 区间 | 颜色 |
|---|---|---|
| 大雕 | ≥112 | 金 #FFB020 |
| 小雕 | ≥104 且 <112 | 绿 #3FB950 |
| 普通 | ≥96 且 <104 | 蓝 #58A6FF |
| 小雷 | ≥88 且 <96 | 橙 #D29922 |
| 大雷 | <88 | 红 #F85149 |

- 在线相对分（百分位，预留）：按同型号群体 μ/σ 算 z 分再查正态 CDF，分档阈值 90/70/30/10。
  当前云端未接入（`ICloudStats` 不可用），走离线绝对分。

### 5.2 置信度与标定等级
- 标定等级 `CalibrationLevel`：`Calibrated`（参数有真机/公开实测出处）/ `Estimated`（规格反推/经验）。
- 离线模式置信度：Calibrated=0.6，Estimated=0.4；在线相对模式=0.9。
- 当前 `baseline.json` 共 9 个型号，**仅 7800X3D 为 Calibrated**，其余 8 个为 Estimated，
  界面与报告对 Estimated 显著水印：「绝对分仅供同型号横向比较，不与厂商内置分数对标」。

### 5.3 参考真机点（用于回归，不要随意改系数）
- 7800X3D OCCT：约 4526MHz @ 0.975V；CPU-Z：约 4896MHz @ 1.127V，折算 SP≈95.2；
  另一版 4896MHz @ 1.1305V→SP≈94.2。两次负载经 V/F 折算后应落在相近区间（可重复性的核心验证）。

## 7. 术语表

| 术语 | 含义 |
|---|---|
| SP / 体质分 | 本软件输出的 0–150 体质评分（自研口径，非厂商分） |
| VDDCR | AMD CPU 核心真实供电电压（整颗），主分使用 |
| VID / Core #N VID | 各核向供电控制器发出的请求电压（CPPC 请求值），非真实供电 |
| V/F 曲线 | 频率-电压对应关系；同代工艺斜率近似恒定 |
| 锚点频率 AnchorFreq | 把不同负载工作点归一化到的统一频率（默认 MaxBoost×0.94，按 25MHz 取整） |
| VRef | 量表里该型号的参考电压（SP=100 对应电压） |
| SVI2 / SVI3 | AMD 供电电压编码协议；Zen3 及以前 SVI2，Zen4/5 为 SVI3 |
| LHM | LibreHardwareMonitor，开源传感器库（含 PawnIO/Ring0 内核访问） |
| PawnIO | LHM 0.9.x 使用的内核驱动，兼容 HVCI |
| HVCI | 内存完整性（内核隔离 / Core Isolation），安全功能，保持开启 |
| SM2 | HWiNFO v7+ 共享内存接口名 `Global\HWiNFO_SENS_SM2` |
| MaxBoost | 标称最大加速频率，满载判定基准 |
| Calibrated / Estimated | 量表参数标定等级：已真机校准 / 估计值 |
