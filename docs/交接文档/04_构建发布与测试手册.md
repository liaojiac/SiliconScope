# 04 · 构建、发布与测试手册

> 目标：在**不要求最终用户安装任何开发环境**的前提下，产出 Windows 解压即用文件夹 zip。
> 开发/打包机可以是 Windows 原生，也可以是 Linux（交叉编译，本项目长期在 Linux 沙盒产出）。

---

## 1. 环境要求

- .NET **8 SDK**。Linux 交叉编译时把 SDK 放在任意目录并加入 PATH（示例 `/home/user/.dotnet`）：
  ```bash
  export PATH=$HOME/.dotnet:$PATH
  export DOTNET_CLI_TELEMETRY_OPTOUT=1
  dotnet --version    # 确认 8.x
  ```
- 首次需要能还原 NuGet（LibreHardwareMonitorLib 0.9.6）；离线环境需本地 NuGet 缓存已含
  LHM 0.9.6 与 Microsoft.WindowsDesktop.App 运行时包（WPF 交叉编译用）。
- 打包 zip：系统自带 `zip`/`unzip`；批处理换行转换用 `perl`（或 sed）。
- Python3（跑逻辑回归，可选但强烈建议）。
- **最终用户机器无需 SDK/运行时**：发布为 self-contained。

---

## 2. 编译

```bash
cd SiliconScope                    # 仓库根（当前版本 V1.0.0）

# Linux/macOS 交叉编译 Windows 目标（关键：EnableWindowsTargeting）
dotnet build SiliconScope.sln -c Release -p:EnableWindowsTargeting=true

# Windows 原生
dotnet build SiliconScope.sln -c Release
```
验收：`Build succeeded. 0 Warning(s) 0 Error(s)`。本项目要求保持 **0 警告**。

---

## 3. 测试与回归

### 3.1 一键逻辑回归（无需 Windows/硬件，Python3）
```bash
python3 run_all.py        # 期望末尾：🎉 全量回归通过；exit 0
```
包含三套：
1. 采集层 `采集层/run_all_tests.py`：A 命名校准 / B 跨主板兼容 / C 探测模式 / D 日志诊断导出 /
   E 真实场景 / F 端到端 / G C# 结构（verify_*.py）。
2. 评分引擎 `评分引擎/verify_scoring.py`：算法 Python 镜像（SP 单调性、三级降级、核心分布、频率不参与评分等）。
3. WPF UI `UI/verify_ui.py`：文件齐全、命名空间、绑定属性存在、XAML 引用一致、版本号、去华硕、重测按钮等
   **130 项静态断言**。

### 3.2 C# 单元测试（需 SDK；采集层是 net8.0-windows，加 EnableWindowsTargeting）
```bash
# 采集层：40 项（含 HWiNFO SM2 解析、FullLoadStability 滑窗、质控等纯逻辑）
dotnet run --project 采集层/tests/Collector.Tests.csproj -c Release -p:EnableWindowsTargeting=true
# 评分引擎：50 项（跨平台 net8.0）
dotnet run --project 评分引擎/tests/ScoringEngine.Tests.csproj -c Release
```
期望均输出 `N passed, 0 failed`。

### 3.3 改代码后的最小验证闭环
1. 改算法/阈值：同步 C# 单测与 Python 镜像（两处口径必须一致）。
2. 改 UI/XAML：在 `UI/verify_ui.py` 增加对应静态断言。
3. 跑 `run_all.py` + 两个 C# 测试工程 + `dotnet build`（0 警 0 错）。
4. **反向验证**：临时把改动改回错误形态，确认新断言会报红，再改回确认转绿（防止写了恒真断言）。
5. WPF 渲染/真机传感器/HWiNFO 属于沙盒盲区，列入发布说明，请真机确认（见 §7 与 05 文档）。

## 4. 发布（publish）

### 4.1 命令（严禁 single-file）
```bash
# 变量按版本调整
OUT="/绝对路径/发布_1.0.0/SiliconScope"
rm -rf "$(dirname "$OUT")"

dotnet publish UI/SiliconScope.csproj \
  -c Release -r win-x64 --self-contained true \
  -p:EnableWindowsTargeting=true \
  -p:PublishSingleFile=false \
  -p:DebugType=none \
  -o "$OUT"
```
- 启动项目是 **UI**（产出 `SiliconScope.exe`），它会带出 Collector.dll / ScoringEngine.dll 及 LHM 全套依赖。
- 必须 `--self-contained true` + `PublishSingleFile=false`（文件夹自包含）。单文件会让 LHM 内嵌
  PawnIO 驱动资源释放失败、读数全 0（真机复现两次，见 Debug 手册 §3.1）。

### 4.2 发布后处理
```bash
cd "$OUT"
rm -f Collector.exe                 # Collector 是 Exe 会被带出一个多余 exe；UI 只需要 Collector.dll
perl -i -pe 's/\r?\n/\r\n/g' 诊断启动.bat     # 批处理转 CRLF（LF 下个别环境异常）
# 放入并转换「使用前必读.txt」为 CRLF
perl -i -pe 's/\r?\n/\r\n/g' 使用前必读.txt
```

### 4.3 发布目录必须存在的关键文件
`SiliconScope.exe`、`LibreHardwareMonitorLib.dll`、`HidSharp.dll`、`Collector.dll`、`ScoringEngine.dll`、
`baseline.json`、`诊断启动.bat`、`使用前必读.txt`，以及 LHM/运行时带出的数百个 dll（正常，含 WinForms
程序集，约 480–500 个文件、未压缩约 160–170MB）。**不应存在** `Collector.exe`。

一键核对：
```bash
for f in SiliconScope.exe LibreHardwareMonitorLib.dll HidSharp.dll Collector.dll ScoringEngine.dll baseline.json 诊断启动.bat 使用前必读.txt; do
  [ -e "$f" ] && echo "OK $f" || echo "缺失 $f"
done
ls Collector.exe 2>/dev/null && echo "!! 残留 Collector.exe" || echo "OK 无 Collector.exe"
```

### 4.4 核对改动确实编进了 dll
.NET 用户字符串是 **UTF-16**，普通 `strings`（单字节）查中文/版本查不到：
```bash
strings -e l SiliconScope.dll | grep -m1 "1.0.0"      # 版本号（UTF-16 #US 堆）
strings SiliconScope.dll | grep -E "RestartCmd"       # 属性名/绑定名在 ASCII #Strings 堆
strings -e l Collector.dll | grep -c "HWiNFO_SENS_SM2"   # 期望 2（映射名+，含互斥体相关）
strings -e l SiliconScope.dll ScoringEngine.dll | grep -c 华硕  # 期望 0
```

## 5. 打包

### 5.1 Windows 解压即用包（exe 包）
注意输出路径是发布目录的**上一级**（`../`），别多写一层 `../../` 放错位置：
```bash
cd 发布_1.0.0
rm -f "../SiliconScope_1.0.0_win-x64.zip"
zip -r -q "../SiliconScope_1.0.0_win-x64.zip" SiliconScope
```
产物落在交付根目录；zip 内顶层应是 `SiliconScope/...`（含使用前必读、无 Collector.exe）。
参考体积：约 72MB、约 494 个文件。
```bash
unzip -l ../SiliconScope_1.0.0_win-x64.zip | grep -E "使用前必读|SiliconScope.exe|Collector.exe"
unzip -l ../SiliconScope_1.0.0_win-x64.zip | tail -1
```

### 5.2 源码包（排除构建产物）
```bash
SRC="/路径/SiliconScope"                   # 仓库根
ST="/tmp/srcstage"
rm -rf "$ST"; mkdir -p "$ST/SiliconScope_1.0.0"
rsync -a --exclude 'bin/' --exclude 'obj/' --exclude '.vs/' --exclude '*.user' \
  "$SRC/" "$ST/SiliconScope_1.0.0/"
cd "$ST"
zip -r -q "/交付根/SiliconScope_源码_1.0.0.zip" "SiliconScope_1.0.0"
```

### 5.3 随附文档
- 发布目录内 `使用前必读.txt`：本版改动、运行步骤、HWiNFO 开关、常见问题、口径、验证情况（CRLF）。
- 交付根放一份 `VX.Y.Z修复说明.md`（面向用户的本版变更与验证）。

## 6. 版本号修改点（发版 checklist）

版本号**唯一权威来源**是 `UI/AppInfo.cs` 的 `Version`，发版至少改/查这几处：
1. `UI/AppInfo.cs`：`Version = "x.y.z"`（界面、报告、历史、日志统一引用）。
2. `UI/MainWindow.xaml`：侧栏显示 `Vx.y.z`。
3. `UI/verify_ui.py`：版本断言（`AppInfo.Version=x.y.z`、侧栏 `Vx.y.z`）。
4. 发布目录名 `发布_Vx.y.z/`、zip 名、源码包顶层目录名、使用前必读标题、修复说明标题。
5. 报告抬头由 `Exporter.Build(..., AppInfo.Version)` 传入，不要再出现 `程序版本：dev`。

## 7. 发布验收清单（交付前逐项打勾）

- [ ] `dotnet build` sln：0 Error / 0 Warning。
- [ ] `python3 run_all.py`：🎉 全量回归通过（采集/评分/UI 三套）。
- [ ] 采集层 C# 测试 40 项、评分引擎 50 项全绿。
- [ ] 新增/变更点有静态断言或单测，并做过反向验证（改错能报红）。
- [ ] publish 为文件夹 self-contained（非 single-file）；已删 Collector.exe；bat/必读为 CRLF。
- [ ] 关键文件齐全（§4.3）；strings 核对版本/关键修复已编入、不该出现的字样为 0。
- [ ] zip 内顶层 `SiliconScope/`、含使用前必读、无 Collector.exe；体积/文件数合理。
- [ ] 使用前必读 + 修复说明写明：管理员运行、解压整个文件夹、**无需关内核隔离**、HWiNFO 共享内存开关、
      打不开跑诊断启动.bat 回传 hosttrace.txt + logs。
- [ ] 明确标注沙盒未覆盖项：WPF 真机渲染、传感器读数、HWiNFO 连接、按钮手感，需用户真机确认。

## 8. Windows 原生构建（备选，参考仓库脚本）
仓库自带 `build_and_test.sh` / `build_and_test.bat` / `build_and_test.ps1`（早期版本，默认路径/步骤
可能略旧，以本手册命令为准）。原生 Windows：
```powershell
dotnet restore
dotnet build --configuration Release
dotnet run --project 采集层/src/Collector --configuration Release   # 控制台演示链路
```
注意：UI 才是正式产品入口（`UI/SiliconScope.csproj` → SiliconScope.exe）；采集层控制台程序仅用于
无 UI 的采集→评分→导出演示与诊断。
