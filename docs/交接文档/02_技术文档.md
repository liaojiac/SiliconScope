## 1. 技术栈

- 运行时：.NET 8 / C#（`Nullable=enable`、`LangVersion=latest`）。
- UI：WPF（`net8.0-windows` + `UseWPF`），手写 MVVM（无 CommunityToolkit/Prism），手写控件与深色主题。
- 传感器：NuGet **LibreHardwareMonitorLib 0.9.6**（MPL-2.0），其 PawnIO 内核驱动读 MSR/传感器。
- HWiNFO：纯托管 `MemoryMappedFile` 只读共享内存，**无第三方包、无驱动**。
- 序列化：`System.Text.Json`；测试：两个自研轻量 xUnit 风格控制台测试工程 + Python 镜像回归。
- 目标：Windows 10/11 x64；评分引擎可在 Linux/macOS 编译运行（纯 net8.0）。

## 2. 解决方案与工程

解决方案 `SiliconScope.sln`，5 个工程：

| 工程 | 路径 | TFM | 类型 | 职责 |
|---|---|---|---|---|
| Collector | `采集层/src/Collector/Collector.csproj` | net8.0-windows | Exe（同时产出 dll 供 UI 引用） | LHM/HWiNFO 采集、质控、日志、诊断、量表读取 |
| Collector.Tests | `采集层/tests/Collector.Tests.csproj` | net8.0-windows | Exe | 采集层单测（40 项） |
| ScoringEngine | `评分引擎/src/ScoringEngine/ScoringEngine.csproj` | net8.0 | dll（跨平台） | V/F 折算、SP 计算、评级、每核 VID 质量、导出 |
| ScoringEngine.Tests | `评分引擎/tests/ScoringEngine.Tests.csproj` | net8.0 | Exe | 引擎单测（50 项） |
| SiliconScope | `UI/SiliconScope.csproj` | net8.0-windows | WinExe（WPF） | 界面、向导状态机、编排采集与评分、设置、历史 |

引用关系：
```
UI (SiliconScope) ──► Collector (Collector.dll)
 │                   │
 └──────────────────┴──► ScoringEngine (ScoringEngine.dll, net8.0)
采集层/Program.cs ──► Collector + ScoringEngine   （独立控制台演示/主链路串联，非 UI 启动项）
```
要点：
- UI 的 `AssemblyName` 是纯 ASCII **`SiliconScope`**（产出 `SiliconScope.exe`），`RootNamespace=SiliconScope.UI`。
- `Collector` 虽是 Exe（含 `采集层/Program.cs`，通过 csproj 显式 `<Compile Include="..\..\Program.cs"/>` 编入），
  UI 引用后发布目录会多出一个 `Collector.exe`，**发布时要删掉**（保留 `Collector.dll`）。
- `baseline.json` 在采集工程内并 `CopyToOutputDirectory`；UI 工程也通过 `Link` 复制一份到输出。
- 交叉编译（Linux 上 build Windows 目标）必须加 `-p:EnableWindowsTargeting=true`。

## 3. 分层架构与端到端数据流

```
┌─────────────────────────────── WPF UI (SiliconScope) ───────────────────────────────┐
│ MainWindow(导航 Run/Result/History/Settings)                                     │
│   └ MainViewModel（持有 AppSettings / EvaluationService / 各子 VM）              │
│        RunViewModel：4 步向导状态机 + DispatcherTimer 实时读数/满载稳定判定        │
│        Result / History /Settings VM                                             │
│        Services：EvaluationService（编排）、AppSettings、HistoryStore、          │
│                 BaselineAdapter（两种 Baseline record 桥接）                      │
└───────────────┬───────────────────────────────────────────────┬─────────────────┘
                │ 调用                                            │ 读写
                ▼                                                 ▼
┌──────────────────────── 采集层 Collector ───────────────────────┐   程序目录文件：
│ LhmCollector（单例 Computer，只 Open 一次）                      │   baseline.json
│   └ RealCollector.Read：UpdateVisitor 全量 Update → 弹性匹配     │   settings.json
│ HwinfoCollector → HwinfoShm.TryRead/ParseCoreVids（可选增强）     │   logs/yyyyMMdd.log
│ CollectorOrchestrator.Validate：合理性→满载→质控 三道门          │   reports/diagnostic_*.json
│ FullLoadStability（60s 滑窗满载稳定性，纯逻辑可单测）            │   history/score_*.json
│ Logger（JSON 行/按天）、DiagnosticBuilder/Store（报告+诊断包）   │
│ Compat（命名规则/合理性）、ProbeMode（探测）、JsonBaselineStore  │
└───────────────┬───────────────────────────────────────────────┘
                │ HardwareFeatures.ToScoreInput() → ScoreInput
                ▼
┌──────────────────────── 评分引擎 ScoringEngine（跨平台）─────────────────────────┐
│ BaselineResolver（三级解析：显式值→代际默认/MaxBoost推算→曲线兜底）               │
│ SpScaler：AnchorVoltage（V/F 线性折算）、CalcSp(Anchored)、五档评级/颜色          │
│ ZenProfile（代际斜率）、VfFit（最小二乘拟合 V/F，R²）                              │
│ ScoreEngine.Score：在线相对/离线绝对/仅曲线 三模式 + 每核最佳最差                 │
│ PerCoreVidQuality：每核 VID 合理性（坏数据置 null）                               │
│ Exporter：JSON + Markdown 报告（控制台链路用；UI 历史用自己的 JSON）              │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**一次评测的完整调用链**（`RunViewModel.DoSample` → `EvaluationService.Evaluate`）：
1. 再次 `CheckEnvironment()`（管理员 / HVCI 信息 / LHM 实测传感器数 / 量表）。
2. 多轮采样 `rounds = SampleDurationMs/SampleIntervalMs`（默认 10000/500=20）：
   - 每轮 `Peek() = LhmCollector.Collect()`（Windows 走 `RealCollector.Read`，否则模拟数据）；
   - 统计满载轮次；每轮顺带 `HwinfoCollector.Collect()` 读每核 VID，跨轮收集；
   - `IProgress` 回调到 UI 画 V/F 点；轮间 `Sleep(500ms)`。
3. 满载轮次占比 < 80% → 返回错误，回到 Step1 继续等满载。
4. `Aggregate(samples)`：电压/频率/温度取**均值**，每核 VID 取**峰值**；LHM 每核 VID 过
   `PerCoreVidQuality`，坏数据置 null。
5. HWiNFO 每核 VID 跨轮取峰 → 再过同一道质量判定 → 通过则覆盖 `PerCoreVIDs`、`Source="LHM+HWiNFO"`。
6. `CollectorOrchestrator.Validate(main)` 三道门；不过返回 `RejectReason`。
7. 量表：`JsonBaselineStore.Get/GetByKeyword` → `BaselineResolver.Resolve`；可选 `VfFit` 本机自标定
   （R²≥0.90 才用拟合斜率覆盖）。
8. `ScoreEngine.Score(ToScoreInput())` 得 `ScoreResult`；组装 UI 的 `EvaluationResult`（含 V/F 点、
   折算参数、数据源、版本号）。
9. 回到 UI 线程：成功 → Step3、`MainViewModel.OnEvaluated`（写历史、加载结果页、跳转）；
   失败 → Step1 + 提示 + 重启实时读数。

## 4. 采集层关键模块

### 4.1 数据契约
- `HardwareFeatures(Model, ZenGeneration, VCore, FrequencyMHz, ReferenceFreqMHz, FullLoadFreqMHz,
  TemperatureC, PerCoreVIDs?, PerCoreClocks?, Source, EnvironmentOk)`，带 `ToScoreInput()`。
  注意 `ReferenceFreqMHz`（基础频率，仅展示）与 `FullLoadFreqMHz`（全核 MaxBoost，满载判定基准）之别。
- 采集层 `Baseline` record 与引擎 `ScoringEngine.Baseline` 字段相似但不同类型，UI 用
  `Services/BaselineAdapter.ToEngine(...)` 桥接，避免跨层耦合。

### 4.2 LhmCollector（Collector.cs）
- 单例 `Computer`（`EnsureComputer` + lock）：只启用 CPU、主板（`IsCpuEnabled/IsMotherboardEnabled=true`，
  内存/GPU 关），`c.Open()` 一次加载 PawnIO；之后每次 `Collect` 仅 `Update`。反复 Open/Close 会导致
  驱动资源释放/重载失败。
- `Collect()`：非 Windows 返回带 `Source="Simulated"` 的模拟数据（仅演示/测试，UI 不得当真）；
  Windows 走 `RealCollector.Read(this)`，失败返回 null（上层据此拒评，绝不给假分）。
- 静态环境：`IsAdministrator()`、`IsMemoryIntegrityEnabled()`（只读注册表 HVCI 状态，仅展示）、
  `CheckEnvironment()`（Windows 即 true，HVCI 不否决）、`ZenMap(model)`（型号关键字→Zen3/4/5/Unknown）。
- `GetFullLoadFreq(model)`：取量表 MaxBoost（缺失退回基础频率），是满载门槛基准。

### 4.3 RealCollector（Collector.Real.cs）
- `UpdateVisitorImpl` 实现 LHM `IVisitor`，对每个硬件 `Update()` 并 `Traverse`。
- 遍历 CPU 硬件所有传感器，按 `SensorType`（Voltage/Clock/Temperature）和 `Compat.SensorNameRules`
  收集候选；核心电压用 `MatchCoreVoltage`：**精确名优先 → 包含关键词兜底 → 排除词拦截 → 数值合理性**。
- 每核 VID/频率用正则 `^Core #\d+ VID$`、`^Core #\d+ \(Effective\)$`、`^Core #\d+$`（LHM 核号 **1 起始**）。
- 无论成败都 `host.SetLastDump(dump)`（全部传感器原始名/值），这是命名/驱动问题的唯一线索。
- 关键量（vcore/avgFreq/pkgTemp）任一 ≤0 即 Warn 并返回 null。

### 4.4 Compat.cs —— 跨主板四层兼容
- ① 弹性匹配 `NameRule(Exact[], Contains[], Exclude[])`：
  - VCore：精确 `VDDCR CPU`、`Core (SVI2 TFN)`；包含 `VDDCR/SVI2/SVI3/Core Voltage/CPU Core`；
    排除 `SoC/Misc/LDO/SMU`（防把 VDDCR SoC 当核心电压）。
  - 温度：精确 `Core (Tctl/Tdie)`，包含 `Tctl/Tdie/Package/CPU Temperature`。
  - 平均频率：精确 `Cores (Average)`，包含 `Average/Core (Avg)/CPU Clock`。
- ② 合理性 `Sanity.IsPlausible(field, v)`（与命名无关的数值区间）。
- ③ 探测自省 `SensorProbe/ProbeSession`（枚举传感器 + 自动匹配，首次运行自动探测）。
- ④ 主板指纹缓存 `BoardCache/BoardFingerprint`（Board/BIOS/LHM 版本）。
- 另有跨主板最后防线 `RationalityCheck`（见下，只看数值区间，命名错也能拦住假大雕）。

### 4.5 质控（Collector.cs）
- `RationalityCheck.Pass`：VCore 0.20–1.60V、温度 0–105℃、平均频率 500–7000MHz，返回具体 reason。
- 满载：`FrequencyMHz ≥ FullLoadFreqMHz × FullLoadThreshold(0.90)`。
- `QualityGate.Pass`：VCore 0.2–1.5V、温度 0–100℃（内含未完成的同步性/稳态时长 TODO）。
- `CollectorOrchestrator.Validate(main)` 按「合理性→满载→质控」返回 `ValidationResults(...RejectReason)`；
  旧的 `Collect()` 还包含完整双源合并 + 诊断报告落盘（控制台链路用），UI 主要用 `Validate`。

### 4.6 FullLoadStability（FullLoadStability.cs，纯逻辑可单测）
- 构造 `(TimeSpan window=60s, requiredRatio=0.90)`，维护窗口内 `(Time, bool loaded)` 队列。
- `Add(now, loaded)` 入队并清窗外数据；`CurrentRatio` 当前满载占比；`StableSeconds` 进度秒数
  （持续满载线性增长、掉载回退、偶发冲高进度很小）；`IsStable` 要求窗口跨度 ≥98% 且满载占比 ≥90%。
- UI 在 800ms `DispatcherTimer` 里 `Add`，达标即自动 `DoSample()`。

### 4.7 HWiNFO 共享内存（HwinfoShm.cs）
- 映射名候选 `Global\HWiNFO_SENS_SM2`、`HWiNFO_SENS_SM2`；互斥体 `Global\HWiNFO_SM2_MUTEX`（同无前缀兜底）。
- `TryRead(out readings, out status)`：逐候选 `MemoryMappedFile.OpenExisting(Read)`；校验状态魔数
  前 4 字节 `HWiS`（激活）/`DAED`（过期，免费版 12h）；从表头读 Reading 段偏移/元素大小/数量，
  **元素步进必须用表头的 ReadingSize**（跨 v1/v2/v3 兼容，勿写死）。
- `Snapshot` 在官方互斥体保护下只读拷贝（拿不到锁退化为无锁读，不阻塞、不失败）。
- Reading 字段偏移（pack=1，小端）：Type u32@0（Volt=2）、SensorIndex@4、Id@8、OrigLabel[128]@12、
  UserLabel[128]@140、Unit[16]@268、ValueCurrent f64@284（其后 Min/Max/Avg）。
- `ParseCoreVids`：只看电压类型，取 **OrigLabel 英文原文**，正则
  `(?:core\s*#?\s*0*(\d+).{0,24}vid)|(?:vid.{0,24}core\s*#?\s*0*(\d+))`（忽略大小写、编译），
  排除词 `soc/misc/ldo/smu/effective/vddio/vddp/vdd25/vdd18/vdd mem/vddg/vddcr soc/1.8/mem/svi3 tfn/svi2 tfn`；
  按核号升序、同核取大；**≥2 核才返回**，否则 null。可匹配真机 `Core 0 VID`（0 起始、无 #），
  排除无数字的汇总 `Core VIDs`。
- `DumpCoreLikeVoltages`：把所有含 core/vid/vddcr 的电压标签落日志，供真机标签差异校准（不靠猜）。
- `NotFoundHint()`：连不上时 best-effort 读注册表 `HKCU\Software\HWiNFO64\Sensors\SensorsSM`
  （=1 开 / 否则关；便携版写 INI 读不到）给出针对性指引。
- `HwinfoCollector`（Collector.cs）包一层：只产出每核 VID（其余量为 0/空），成功 Info「已获取」、
  连上但解析不到 ≥2 核 Warn 带标签 dump、连不上 Info 回退 LHM。

### 4.8 日志与诊断
- `Logger`（进程单例 `Logger.Instance`）：双输出（Console + 按天文件 `logs/yyyyMMdd.log`），
  JSON 行、四级（Verbose/Info/Warn/Error）、线程安全 lock、内存缓冲供打包；方法签名统一
  `(msg, context=null)` 与 `Error(msg, exception=null, context=null)`。便携优先用程序目录而非 %LocalAppData%。
- `DiagnosticBuilder` 组装 `DiagnosticReport`（环境信息、传感器 SensorDump、字段解析 FieldResolution、
  校验结果 ValidationResults、评分快照）；`DiagnosticStore.Save` 落 `reports/diagnostic_时间戳_短id.json`、
  `RetainLatest` 保留 10 份、`PackDiagnosticBundle` 打 `诊断包/诊断包_时间戳.zip`（logs+reports+缓存+README）。

### 4.9 量表
- `baseline.json`（9 型号），`JsonBaselineStore` 精确字典 + 关键字模糊匹配；缺失型号 UI 报
  「未收录型号，请在 baseline.json 补充」。字段：Model/ZenGeneration/VRef/ReferenceFreqMHz/Priority/
  MaxBoostMHz/AnchorFreqMHz/SlopeMvPerMhz/CalibrationLevel。

## 5. 评分引擎关键模块（ScoringEngine.cs / Exporter.cs，跨平台）

### 5.1 参数三级解析 `BaselineResolver.Resolve(Baseline)`
- 锚点频率：量表 `AnchorFreqMHz` > 0 用之；否则 `round(MaxBoost × 0.94 / 25) × 25`（`ZenProfile.AnchorToBoostRatio=0.94`）。
- V/F 斜率：量表 `SlopeMvPerMhz` > 0 用之；否则按代际 `ZenProfile.DefaultSlope`：
  Zen/Zen+/Zen2=0.30，Zen3=0.35，**Zen4=0.41**，Zen5=0.45，未知=0.40（mV/MHz）。
- 产出 `ResolvedBaseline`（含 AnchorSource / SlopeSource，供界面展示来源）。

### 5.2 V/F 折算与 SP（SpScaler）
- 锚点电压（线性带截距，**不是等比乘法**）：
  `V_anchor = V_meas + (slope/1000) × (AnchorFreq − F_meas)`。
- SP：`SP = clip(100 + (VRef / V_anchor − 1) × 300, 0, 150)`。电压越低分越高。
- slope/anchor 为 0 时自动退回不折算（旧量表仍可用）。
- 意义：OCCT（重负载、低频高压差）与 CPU-Z（轻负载、高频）采到不同工作点，沿 V/F 直线归一化到
  同一锚点后才可比，这是结果可重复的关键（真机两点折算后都落在 SP≈94–95）。

### 5.3 三种模式（ScoreEngine.Score）
- `OnlineRelative`：`ICloudStats` 可用且有该型号 μ/σ 时，算 z 分→正态 CDF 百分位（Abramowitz-Stegun 近似），
  置信度 0.9，按百分位评级。当前云端未接入（构造传 null）。
- `OfflineAbsolute`：有 VRef 时，按 SP 评级；置信度 Calibrated 0.6 / Estimated 0.4，note 不同。
- `CurveOnly`：无 VRef，返回 0 分与「缺少参考电压，仅显示原始曲线」。
- 每核最佳/最差：VID 最小=最佳核、最大=最差核，输出 `Core#i`（UI 解析下标）。

### 5.4 VfFit
- `Fit(IEnumerable<(freq,volt)>)` 最小二乘拟合直线，返回斜率/截距/R²/点数；UI 自标定要求 R²≥0.90
  且斜率为正才用本机斜率覆盖量表（多点频率方差不足时不启用）。

### 5.5 PerCoreVidQuality
- `MinPlausibleFullLoadVid=0.75`：满载每核请求电压最大值低于此 → 全停在最低档占位值，判无效。
- `DetachMargin=0.25`：当整颗 VDDCR>0.90V 而每核最大值比它低 0.25V 以上 → 与真实供电脱节，判无效。
- `Sanitize` 无效返回 null（下游不输出核间排名/分布）。

### 5.6 Exporter（控制台链路报告）
- `ScoreReport`/`CoreRow`；`ToJson/ExportJson`、`ToMarkdown/ExportMarkdown`、`ExportBoth`。
- `Build(ScoreInput, Baseline, ScoreResult, appVersion="dev")`（UI 传 `AppInfo.Version`）；Markdown 含
  五档、每核 VID 条形图、物理事实说明、Estimated 水印、V/F 参数、算法来源、口径提示。
- 注意：UI 主流程不写 Markdown，历史用 `HistoryStore` 的 JSON；Exporter 主要服务采集层 `Program.cs`
  与命令行/导出场景。

## 6. WPF UI（UI 工程）

### 6.1 MVVM 骨架（零依赖）
- `ViewModelBase`：`INotifyPropertyChanged` + `Set<T>(ref,value)` + `Raise`。
- `RelayCommand`（仅无参 `Action`，**不支持 CommandParameter**）：`CanExecute` 委托 + `Notify()`
  手动触发 `CanExecuteChanged`。需要刷新按钮可用性时，在相关属性 setter 里调 `RefreshCommands()`。

### 6.2 导航与共享状态（MainViewModel）
- `enum NavPage { Run, Result, History, Settings}`；`Page` + `IsRun/IsResult/...`；`Go(page)`
  （进 History 会 `Refresh()`）。
- 持有全局唯一 `AppSettings`、`EvaluationService`、四个子 VM；`OnEvaluated(result)`：写历史、
  `Result.Load`、跳结果页、更新状态条。
- **构造函数不碰硬件**；`StartBackgroundProbe()` 在主窗口 `Loaded` 后用 `Task.Run` 后台自检，
  失败只改状态条，绝不拖垮启动。

### 6.3 向导状态机（RunViewModel，核心交互）
- `Step`：0 自检 / 1 等待满载 / 2 采样中 / 3 完成。属性变化触发 `RefreshCommands`。
- 命令：
  - `StartCmd`：`!Busy && Step==0` → `DoEnvironment`（后台自检；过则 Step1+StartLive，不过留 Step0）。
  - `StartSampleCmd`：`!Busy && Step==1 && FullLoadStable` → `DoSample`（手动按钮，门槛与自动一致）。
  - `CancelCmd`：定时器在跑时可停。
  - `RestartCmd`：`!Busy && Step==3` → `Restart()`=`ResetWizard()`+`DoEnvironment()`，一键重测。
  - `ViewResultCmd`：`Step==3` → 跳结果页。
- `ResetWizard()`：停定时器、清 EnvItems/LivePoints、`_stability=null`、稳定秒数/满载标志/进度复位、
  提示复位、Step=0。**修重测 bug 的关键**：完成态 Step=3 原本无任何复位入口，只能重启软件。
- `StartLive()`：800ms `DispatcherTimer`，每 tick `Peek()` 刷新实时值、更新瞬时满载灯、向
  `FullLoadStability.Add`、推进稳定秒数；`IsStable` 达标置 `FullLoadStable=true` 并自动 `DoSample()`。
- `DoSample()`：停定时器、Step2、Busy、约 10s 进度；后台 `Evaluate(progress)`，回 UI 线程：
  成功 Step3+OnEvaluated；失败 Step1+提示+StartLive。
- 后台线程更新 UI 一律 `Application.Current.Dispatcher.Invoke`；进度用 `Progress<T>`（自动回 UI 线程）。

### 6.4 服务与模型
- `EvaluationService`：单例 `LhmCollector`；`CheckEnvironment/Peek/Evaluate/Aggregate/TryOpenLhm`；
  内含 `FixedBaselineStore`（自标定覆盖斜率）。详见 §3 调用链。
- `AppSettings`：`settings.json` 读写（损坏回默认并 Warn），`Apply()` 把设置写入 `CollectorOptions`
  （Interval=500、Duration=10000、SampleRounds=MultiSample?0:1 等）。
- `HistoryStore`：`history/score_yyyyMMdd_HHmmss.json`，UTF-8、Indented、UnsafeRelaxedJsonEscaping；
  LoadAll 倒序、Delete（文件名净化）、OpenFolder、Prune 保留 N；IO 失败只 Warn 不阻断。
  `HistoryEntry.VfPoints` 用 `double[][]`（值元组不能可靠 JSON 序列化），与 `EvaluationResult` 互转。
- `BaselineAdapter.ToEngine`：采集层 Baseline → 引擎 Baseline。
- 模型：`EvaluationResult`（UI 全字段，含 IsEstimated）、`HistoryEntry`（持久化形态）。

### 6.5 视图、控件、主题
- Views：RunView（向导四步）、ResultView（环形分、V/F 图、每核条、参数与说明、Estimated 水印）、
  HistoryView（列表/详情/删除/打开目录）、SettingsView（HWiNFO 开关、采样、阈值、自标定、日志、关于）。
- Controls（手写）：`RingGauge`（环形仪表）、`VfChart`（V/F 散点+拟合线，采样时绑 LivePoints）、
  `CoreBars`（每核 VID 条形）。
- Theme/Styles.xaml：深色 GitHub 风。颜色 `*Color` 与画刷 `*Brush` **分别命名**（曾因同名键冲突崩溃）；
  文本画刷 TextBrush=#E6EDF3、MutedBrush=#8B949E、DimBrush=#6E7681，强调橙 #FF6B35 等。
  所有数值/文本都要显式给浅色前景，禁止依赖默认黑字（曾出现深色背景黑字看不清）。
- 启动：`App.xaml.cs` 静态构造最早初始化 Logger 并挂 `AppDomain.UnhandledException` /
  `TaskScheduler.UnobservedTaskException`；`OnStartup` 挂 `DispatcherUnhandledException` 后**手动**
  `new MainWindow().Show()`（不用 StartupUri）；任何阶段失败都尽量写日志 + Win32 MessageBox，消除一闪而过。

## 8. 跨平台 / 交叉编译说明

- 只有 `ScoringEngine` 是纯 net8.0，可在 Linux/macOS 直接 `dotnet run`/测试；采集层与 UI 是
  net8.0-windows（LHM、注册表、WPF、PawnIO）。
- Linux 沙盒**交叉编译** Windows 程序集：所有 build/publish 加 `-p:EnableWindowsTargeting=true`，
  需本地 NuGet 缓存已有 LHM 0.9.6 与 WindowsDesktop runtime pack（可离线）。
- 沙盒**不能**用 Wine 跑 WPF 冒烟（缺 .NET8 桌面 API）。因此沙盒侧验证手段是：
  ① dotnet build/publish 编译期；② net8.0 引擎单测；③ net8.0-windows 采集测试工程（纯逻辑部分）；
  ④ Python 镜像回归；⑤ `verify_ui.py` 对 XAML/CS 做静态结构/绑定/命名一致性扫描。
  **WPF 实际渲染、真实传感器、HWiNFO 连接必须 Windows 真机验证**（靠 logs / reports / 截图回传）。
