# 05 · 已知限制、真机验证边界与后续规划

> 诚实标注「哪些已被验证、哪些没有、哪些不能做」，避免接手者误判完成度。

---

## 1. 沙盒（Linux 交叉编译）能做与不能做

### 能做（已纳入每次发布的自动化）
- `dotnet build` sln（含 WPF 工程，用 `-p:EnableWindowsTargeting=true`）：编译期错误/警告。
- `dotnet publish` 产出 Windows self-contained 文件夹。
- 纯 net8.0 的评分引擎单测（50）、net8.0-windows 工程里不依赖硬件的纯逻辑单测（采集 40）。
- Python 镜像回归（采集/评分）与 `UI/verify_ui.py` 静态结构/绑定/命名/版本扫描（130）。
- 用 `strings` 核对程序集是否编入关键字符串/命令名/协议名。

### 不能做（必须 Windows 真机）
- **WPF 实际渲染**：布局、颜色可读性（黑字）、字体、控件命中、页面切换手感。
- **LHM/PawnIO 真实传感器**：Computer.Open、驱动加载、电压/频率/温度读数、传感器数量与命名。
- **HWiNFO 共享内存**：SM2 连接、互斥体、真实标签解析（已由用户真机 v8.34 验证成功）。
- 管理员提权、HVCI 开启状态、GBK/936 区域下 apphost 行为、杀软交互。
- 因此：**沙盒全绿 ≠ 真机可用**，每次发布都要在交付说明里列出待真机确认项，并依赖用户回传
  `logs/`、`reports/`、截图、`诊断启动.bat` 的 hosttrace 来闭环。

## 2. 真机验证现状（基线机：Win10 22H2 / 7800X3D / HWiNFO v8.34）

已真机确认：
- 启动可靠性（五连修后）：HVCI 开启 + 管理员运行，正常进入主界面，LHM 读到约 74 个传感器。
- 满载流程：OCCT/CPU-Z 满载、持续满载约 1 分钟自动采样、约 10 秒出分。
- HWiNFO 每核 VID（SM2 接通后）：开启共享内存可拿到 Core 0…7 VID；不开 HWiNFO 主分照出、
  仅无核间分布（符合设计）。
- 评分可重复性：OCCT（约 4526MHz）与 CPU-Z（约 4896MHz）两点经 V/F 折算后 SP 落在相近区间（约 94–95）。
- 本机历史成绩落盘与查看。

仍建议每版真机回归（沙盒盲区）：
- 完成页「↻ 重新评测」「查看评分详情」的实际点击与一键重测手感（静态校验已覆盖逻辑，未真机点）。
- 去华硕后各界面/报告文案在真机的换行与显示。
- 不同主板/BIOS、不同 Zen 代际（Zen3/Zen5）、不同 HWiNFO 语言/版本的传感器与标签适配。

## 3. 数据与校准现状（重要）

- `baseline.json` 共 9 个型号，**仅 `7800X3D` 是 `Calibrated`**（VRef=1.070、ReferenceFreq=4200、
  MaxBoost=5000、Anchor=4800、slope=0.41，来自真机/公开口径）；其余 8 个（7950X/7900X/7700X/
  5800X3D/5900X/9950X/9900X/9700X）均为 `Estimated`（规格反推/经验值），界面与报告已水印提示。
- 评分系数（scale=300、五档 112/104/96/88、锚点比例 0.94、代际斜率、满载阈值 0.90、质量门限）
  是在单一真机型号上校准/确定的，**通用性靠 V/F 折算 + 代际画像 + 合理性兜底**，但跨型号绝对分
  仍需更多真机/众包样本收敛。无新证据不要改系数。
- 在线相对分（百分位、`ICloudStats`）未接入，当前全部走离线绝对分；云端 μ/σ、排行榜、账号体系
  仅预留接口。

## 4. 悬置 / 未启动方向

1. **摆脱 HWiNFO 的自研每核 VID（SVI3 解码）**
   - 现状：Zen4/5 每核 VID 依赖 HWiNFO 共享内存（LHM 套 SVI2 公式给出 ~0.43V 错值被丢弃）。
   - 可能路径：借 PawnIO/LHM 读 MSR `0xC0010293` 的原始 8 位 VID code（LHM 内部读到了但不对外暴露
     raw code），再自行按 **SVI3** 编码表换算每核请求电压。
   - 启动前必须先核实：Zen4/Zen5 每核 VID 的精确 SVI3 编码/步进表；PawnIO 能否在不修改 LHM 的前提下
     取到 per-core raw code；与 HWiNFO 真值逐核对、多颗 CPU 多轮真机校准。未完成前保留 HWiNFO 方案。
2. **云端 / 众包 / 排行榜 / 账号**：`ICloudStats`、早期文档里的云端服务均为预留（曾返回 501）。
   需要先设计上传数据口径、隐私（当前承诺纯本地不上传）、同型号样本去噪与 μ/σ 收敛规则。
3. **众包传感器映射库 / 主板指纹缓存**：Compat 四层兼容里预留了探测与指纹缓存，跨主板命名库可做
   在线/离线更新机制（当前主要靠弹性匹配 + 合理性兜底）。
4. **质控 TODO**：`QualityGate` 注释里的「采样同步性 ≤16ms、稳态时长 ≥30s」尚未量化实现
   （现由 10s 窗口均值 + 满载占比 + 60s 稳定确认间接覆盖），可按需补采时长/方差统计。

## 5. 已知技术债 / 注意事项

- ~~顶层 README 过时~~（**已解决**）：顶层 README 已重写为英文（开源首页），
  中文版另存 `README.zh-CN.md`，版本 V1.0.0。
- ~~内部版本号与公开版本不一致~~（**已解决**）：公开版本统一为 **V1.0.0**，
  版本一律看 `UI/AppInfo.cs`；源码包顶层目录命名 `SiliconScope_1.0.0`。
- 采集层 `Collector` 工程是 Exe（含独立 `Program.cs` 演示链路，使用 FakeLhm 模拟数据），UI 引用后
  发布会带出多余 `Collector.exe`，发布脚本需删除（保留 dll）。若日后把 Collector 改成纯类库，
  可同时迁移/移除 Program.cs 与 csproj 的显式 Compile，省去这一步。
- `RelayCommand` 仅支持无参命令（不支持 CommandParameter）；需要参数命令时要先扩展它。
- 历史 `HistoryEntry.VfPoints` 用 `double[][]` 而非值元组（JSON 序列化可靠性），改模型时保持可反序列化
  旧历史文件（`ToResult` 已对缺失/短数组做了防御）。
- 仓库根有大量 V1.3–V1.7 迭代说明 md（归档性质，部分命令/结论已被取代），查阅时先看
  `附录C_历史文档与资料索引.md` 的「现行/归档/过时」标注。

## 6. 建议路线图（按优先级，供负责人决策）

1. 多真机覆盖：补 Zen3/Zen5 与更多主板的传感器/HWiNFO 标签适配，把高频型号从 Estimated 升 Calibrated。
2. 数据收敛：在明确隐私与授权前提下设计众包上传（满载工作点 + 型号 + 主板/BIOS/HWiNFO 标签），
   反哺 baseline 与命名库；在此之前维持纯本地。
3. （可选）自研 SVI3 每核 VID，去掉对 HWiNFO 的依赖（见 §4.1，工作量与校准成本高）。
4. 工程整洁：重写顶层 README；评估 Collector 改纯类库；补 QualityGate 稳态/同步性量化项。
5. UI 增强：历史趋势对比、报告导出（UI 侧接 Exporter 出 Markdown/JSON）、更多语言等。
