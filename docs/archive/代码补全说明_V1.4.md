## 二、★ 本轮捕获并修复的关键 Bug

### Bug：评分路径仍残留「频率折算」→ 假大雕

**症状**：`7800X3D VCore=1.046V @ 5050MHz` 算出 **SP=150（满分/大雕）**，而该电压实际只是普通水平。

**根因**：`ScoreEngine.Score()` 里 `v_equiv = VCore * (ReferenceFreqMHz / FrequencyMHz)` 仍把频率折算进公式。高频满载时折算后电压远低于 VRef，公式误判为"大雕"——**这正是《频率折算勘误.md》禁止的，但代码没同步改**。

**修复**：
```csharp
// 修复前
double vEquiv = input.VCore * (baseline.ReferenceFreqMHz / input.FrequencyMHz);
// 修复后 ★ 评分用实测电压，频率仅质控
double vEquiv = input.VCore;
```
`Collector.cs` 的满载判定保留频率逻辑（`FrequencyMHz ≥ ReferenceFreqMHz × 0.95`）——频率从"评分变量"降级为"质控变量"，符合勘误。

**验证**：修复后 `1.046V → SP=101.1（普通）`，且"同电压不同频率 → SP 完全相同"。

## 五、诚实提示（务必知悉）

1. **C# 代码未在 .NET 上真实编译**：沙盒无 .NET SDK，仅做了**静态结构校验 + Python 逻辑等价验证**。Windows 首次编译可能有 record / 模式匹配语法的细微调整（.NET 8 应原生支持，风险低）。
2. **`LhmCollector.Collect()` 默认走 `Simulate()`**：返回模拟数据，逻辑跑通但不读真机。**真机采集需按第四章启用真实代码块**。
3. **VRef 仍是估算值**（规格反推）：绝对 SP 标注"仅供参考"真实必要，需样本库积累后校准。
4. **云端/在线模式**：当前用模拟分位表（`mu=100, sigma=6`），真实对接只需替换 `ICloudStats` 实现（接口已预留）。
5. **Python 验证层**：仅为"逻辑自洽证明"，生产以 C# 为准。若你不打算装 Python，可忽略 `*.py`，直接用 `build_and_test.*`。
