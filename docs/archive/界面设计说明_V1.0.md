# CPU 体质评分软件 · 界面设计说明 V1.0

> 配套：可交互原型 `CPU体质评分_界面原型.html`（双击用浏览器打开，可点击走完整流程）
> 目标：让**没有命令行经验**的用户也能独立完成一次可信的体质评测
> 状态：设计稿，待你评审；确认后再进入 WPF 实现

---

## 一、设计定位

### 1.1 核心矛盾

这个软件的技术内核很硬（V/F 折算、质控门禁、CPPC 请求值…），但用户是**普通超频玩家**。
界面要解决的不是"展示所有数据"，而是：

1. **让人敢用**：不知道什么是 VDDCR 也能跑完流程
2. **让人信服**：分数怎么来的必须看得见（否则和玄学没区别）
3. **不出假结果**：该拒评时明确拒评，而不是给一个好看的分数

### 1.2 设计原则（贯穿全部页面）

| 原则 | 体现 |
|------|------|
| **引导式流程** | 评测是 4 步向导，每步只做一件事，不给用户选择困难 |
| **算法透明** | 折算参数、来源、标定等级全部展示在结果页，不做黑盒 |
| **诚实优先** | Estimated 水印、每核 VID 物理事实、口径误差，全部显式告知 |
| **拒评比给分更重要** | 未达满载/环境异常 → 明确拒绝并说明原因与修复方法 |
| **本地闭环** | 设置页明示"不上传任何数据"，建立信任 |

### 1.3 视觉方向

深色主题，与硬件监控类工具（HWiNFO、GamePP）一致，长时间烤机时不刺眼。
强调色用 **AMD 橙红 #ff6b35**，SP 分数用大号数字 + 环形进度。

## 二、信息架构（5 个页面）

```
┌─ 概览 Dashboard ──────── 上次结果 + 环境自检 + 最近三次
├─ 开始评测 Run ────────── 4 步向导（自检→负载→采样→完成）
├─ 评分详情 Result ─────── SP 分 + V/F 图 + 核心分布 + 参数来源
├─ 历史记录 History ────── 全部记录 + 折算效果对比 + 数据管理
└─ 设置 Settings ──────── 数据源 / 评分 / 日志隐私 / 关于
```

侧边导航固定，顶栏显示传感器状态与当前模式。

## 三、逐页设计规范

### 3.1 概览（首屏）

**目标**：3 秒内回答"我这颗 CPU 怎么样"。

| 区块 | 内容 |
|------|------|
| Hero | 上次 SP 大数字（环形）+ 评级 + 一句话解读 + 两个动作按钮 |
| 四个数据卡 | 型号 / VDDCR 电压 / 稳态频率 / 温度 |
| 环境自检卡 | 管理员、核心隔离、LHM 驱动、量表、HWiNFO（五项 ✓/○） |
| 最近三次 | 含折算后一致性说明（129/85 → 95.2/95.1） |

> 为什么要放"最近三次一致性"：这是**信任的第一来源**——用户看到不同烤机软件结果一致，才会信这个分。

### 3.2 开始评测（核心向导）

4 步，每步一个明确动作：

| 步 | 名称 | 界面重点 | 用户动作 |
|----|------|---------|---------|
| 1 | 环境自检 | 4 项检查清单逐条 ✓ | 无（自动） |
| 2 | 等待满载 | 黄色提示框 + 实时四项读数 + 门槛说明 | 运行 OCCT 等，点"已满载" |
| 3 | 多点采样 | **实时 V/F 散点图逐点出现 + 拟合直线** | 无（自动 6 轮） |
| 4 | 完成 | SP + 评级 + 跳详情 | 无 |

**第 3 步的实时 V/F 图是本设计的亮点**——它把抽象的"折算"变成看得见的直线，用户能直观理解"为什么不同负载结果一致"。

第 2 步必须显示**具体门槛**（4500MHz），而不是笼统的"请满载"。

### 3.3 评分详情

| 区块 | 作用 |
|------|------|
| **SP 大数字 + 环形 + 评级徽章** | 主结论，一眼看到 |
| 结果元信息 | 型号、Zen、负载、稳态频率/电压/温度、锚点 |
| **V/F 工作点图** | 两点 + 拟合直线 + 锚点线 + 折算后电压 |
| **核心电压分布** | 8 核横向柱状（本次 min/max 归一化）+ 最优/最弱标记 |
| **参数与来源表** | V_ref / 锚点 / 斜率 / 标定等级 / 折算后电压，逐条标来源 |
| 导出 | 导出报告（JSON+MD）、导出诊断包 |

**必须保留的三处诚实标注**（已设计进原型）：
1. 每核 VID 是 CPPC 请求值、统一供电、核间排名仅供参考、不声称能复刻华硕每核 SP
2. 离线评分仅供参考 + VID/VDDCR 口径差 ±10mV → SP ±3~5 分
3. Estimated 型号水印（原型提供切换按钮演示两种状态）

### 3.4 历史记录

- 全部记录表（含一条**被拒评**的记录，演示"宁可拒评"）
- 折算效果对比小表（129.2/84.8 → 95.2/95.1，分差 44.4 → 0.08）
- 数据管理：导出 / 打包诊断包 / 清空

### 3.5 设置

分三组，**每项都有说明文字**（普通人看不懂"探测模式"这四个字）：

- 数据源：HWiNFO 增强（默认关，手动开）、探测模式、多轮采样、满载阈值
- 评分与量表：量表文件、自标定拟合、云端分位表（标注"接口预留"）、开机自启
- 日志与隐私：日志级别、诊断报告保留份数、**数据上传 = 本地闭环**

## 四、状态覆盖清单（实现时必须全部处理）

| 状态 | 界面表现 |
|------|---------|
| 首次启动（无历史） | Hero 显示"尚未评测" + 引导按钮；历史页空态 |
| 环境自检失败（核心隔离开启） | 红色阻断页 + 关闭方法说明 + 拒绝开始评测 |
| 非管理员 | 阻断页 + "以管理员身份重启"按钮 |
| 模型未收录 | 阻断 + 提示补充量表，而非崩溃 |
| 未达满载 | 第 2 步黄色提示 + 实时频率低于门槛时按钮禁用 |
| 质控不通过（电压/温度越界） | 拒评页 + 具体越界值 |
| VRef 缺失 | CurveOnly：只显示曲线与工作点，明确"不给分" |
| Estimated 型号 | 结果页顶部黄色水印 + 参数表标"估计值" |
| HWiNFO 已启用 | 概览自检卡显示 ✓，数据卡标注"双源" |
| 采集中 | 进度条 + 实时图 + 可中断 |

## 五、技术栈建议

| 方案 | 评价 | 建议 |
|------|------|------|
| **WPF (.NET 8)** | 原生、性能最好、与现有 .NET 8 工程零摩擦、MVVM 成熟 | ⭐ **推荐**——你只做 Win10/11，无跨平台诉求 |
| WinUI 3 | 更现代，但生态/稳定性/工具链仍弱于 WPF | 备选 |
| Avalonia | 跨平台，但硬件层仍 Windows-only，跨平台无实际收益 | 不必要 |
| WinForms | 能跑但视觉上限低，做不出上述图表与动效 | 不推荐 |

**架构要点（关键）**：
- 评分引擎 `ScoringEngine`、采集层 `Collector` **已是纯 C# 类库**，UI 层只做调用与展示，**不要再往核心里塞界面逻辑**
- 用 MVVM（CommunityToolkit.MVVM）：`MainViewModel` / `RunViewModel` / `ResultViewModel`
- 图表建议：**不用重型图表库**。V/F 散点与核心柱状都很简单，用 **WPF 原生 `Canvas`/`Shape` + 少量换算** 即可（原型里的 SVG 逻辑可直接移植为 WPF `Line`/`Ellipse`）
- 异步：采集与采样必须 `async/await` 或 `Task.Run`，**严禁阻塞 UI 线程**（烤机时 UI 卡住会让人以为程序死了）

## 六、与现有代码的对接点

| 界面元素 | 数据来源 |
|---------|---------|
| 环境自检 5 项 | `LhmCollector.CheckEnvironment()` / `IsAdministrator()` / 传感器计数 |
| 实时四项读数 | `HardwareFeatures`（VCore / FrequencyMHz / TemperatureC / 功耗） |
| 实时 V/F 散点 | 采样过程中累积的 (F,V) 点 → `VfFit.Fit()` 拟合 |
| SP 与评级 | `ScoreEngine.Score()` → `ScoreResult` |
| 核心分布 | `ScoreInput.PerCoreVIDs` → `Exporter.Bar()` 的 min/max 归一化逻辑 |
| 参数来源表 | `BaselineResolver.Resolve()` 返回的 `SlopeSource` / `AnchorSource` / `CalibrationLevel` |
| 导出 / 诊断包 | `Exporter.ExportBoth()` / `DiagnosticStore.PackDiagnosticBundle()` |

## 八、诚实提示

- 原型用**模拟数据**（7800X3D / SP 95.2 / 8 核 VID），流程是真实逻辑，数值是演示值
