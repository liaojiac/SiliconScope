## 二、澄清要点

**`LibreHardwareMonitorLib`（开源库 DLL）≠ `LibreHardwareMonitor`（独立 GUI 程序）**

- 当前 V1.6 用的是**方式 A**：把 `LibreHardwareMonitorLib` NuGet 包**直接编译进本软件**
- → **不产生任何后台服务，也不需要用户装或开任何 LHM 程序**
- WMI（方式 B）才涉及后台进程，且已被否决

## 三、为何否决 WMI

1. ✅ 方式 A → 用户零负担（不用装/开 LHM，无后台服务）
2. ✅ 兼容层（V1.6 四层防御）已覆盖命名差异 → WMI 核心卖点（命名统一）不再有优势
3. ✅ 无自启进程、无权限/生命周期负担
4. ❌ WMI 的代价（后台进程 + 权限 + 自启维护）实打实，收益却被兼容层抵消 → 得不偿失
