# 频率折算 — 设计勘误说明

> 适用：《评分算法详细设计 V1.0》§4.2「跨 Zen 归一化」
> 状态：已通过端到端验收验证并修正（2026-09-18）

## 问题本质

原文档公式：
```
V_equiv = V_meas × (F_ref / F_meas)
SP = 100 + (V_ref / V_equiv − 1) × Scale
```

**在「体质评分」场景下是错误的**。原因：

体质评分比较的是**同一型号、同频下谁电压更低**。采集到的 `V_meas` 是**当前稳态频率 `F_meas` 下的真实需求电压**——这颗 CPU 在 5GHz 需要 1.02V，这就是它的体质事实。

若强行折算回额定频率（如 4.2GHz）：
```
V_equiv = 1.02 × (4200/5000) = 0.857V
SP = 100 + (1.05/0.857 − 1) × 300 ≈ 267 → clip 150
```
**正常工作电压被算成"大雕"，公式失真**。端到端验收正是捕获了这个 bug。

## 根本原因

频率折算公式**原本用于不同场景**：已知某 CPU 的「频率-电压曲线」，把**同一颗 CPU**在不同频率的采样点归一化到同一基准点做曲线拟合。

但我们的量表 `V_ref` 是**额定频率下的参考电压**，而采集电压是**满载稳态电压**——两者本就是同一工作点（满载≈最大频率），**不该再折算**。

## 修正决策（最终版）

> **评分一律使用实测稳态电压 `V_meas`，频率 `F_meas` 仅用于质控，不参与 SP 公式。**

具体：
1. **采集阶段**：记录 (V_meas, F_meas, T)，要求 F_meas 达到目标负载阈值（如额定频率的 95%）才算稳态
2. **质控阶段**：F_meas 过低 → 判定"未满载"，拒绝评分（避免待机低电压虚高）
3. **评分阶段**：`SP = 100 + (V_ref / V_meas − 1) × Scale`，**直接用 V_meas**

## 跨代可比性如何保证？

不靠频率折算，而是靠**两级机制**：

| 层级 | 机制 | 说明 |
|------|------|------|
| **型号内** | 直接比较 V_meas（同型号同频天然可比） | 离线模式主打 |
| **跨型号** | 云端分位表（每型号独立 μ/σ）把 SP 映射为百分位 | 在线模式主打 |

华硕 SP 本身就是**型号相关的绝对分**（每个型号各自 SP=100 的基准），"大雕=该型号 Top %"——这与我们的设计完全对齐。**不需要靠频率折算来造"跨代可比性"**。
